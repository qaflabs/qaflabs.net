# Commit conventions

Rules for git commit message titles in this repository.

## 1. The "If merged, this commit will" test

Every commit title must complete the sentence:

> If merged, this commit will **\<commit title\>**.

If the resulting sentence reads as grammatical English and makes sense, the title passes. If it does not, rewrite it.

This forces titles to:

- Use imperative mood ("Add", "Fix", "Hide", "Remove", "Refactor", "Move", "Restore").
- Describe the effect of merging the commit, not the author's past action.
- Skip prefixes like `fix:`, `feat:`, `chore:`, which break the sentence.

| Title | Verdict |
| --- | --- |
| `Hide characters and elements from @ mention menu when reference limit is full` | Pass |
| `fix: hide characters from menu` | Fail: `fix:` breaks the sentence |
| `Hidden references on limit` | Fail: past participle, not imperative |
| `Fixing the references limit bug` | Fail: gerund, not imperative |
| `References limit fix` | Fail: noun phrase, not a verb |
| `Move scale-factor constant from editors to core` | Pass |

## 2. Capitalization

The first character of the title is always a capital letter. The rest follows normal English casing: proper nouns, acronyms and file or symbol names stay as written (`Add useHandleImageItemUpscale hook to core` passes).

## 3. Single line by default

Always write a single-line title unless the user explicitly asks for a multi-line message. Do not promote a commit to multi-line on your own judgement (many files, unrelated-looking changes).

When the user does ask for one:

1. Line 1: a title that passes rules 1 and 2.
2. A blank line.
3. The body opens with the literal phrase `This commit entails the following changes`.
4. Then an unordered list (`-` bullets), one change per item.

```
Refresh references workflow

This commit entails the following changes
- Hide characters and elements from @ mention menu when reference limit is full
- Add commit-conventions rule under docs/agents/rules/
```

## 4. No attribution trailers

Never append `Co-Authored-By:` or any other "generated by" attribution. The message is only the title (and, when requested, the body from rule 3).

## 5. Check before committing

1. Read the title aloud after "If merged, this commit will".
2. Verify the first character is uppercase.
3. Confirm the commit is single-line unless the user asked for multi-line.
4. If any check fails, rewrite and re-check.
